# Auditoría de Reglas de Negocio — 2026-07-25

contra el código actual (no solo contra docs previos). Realizada con 5 auditorías
paralelas por rango. Fuente de verdad para actualizar el backlog.

Leyenda de estado:
- **OK** — Implementado y verificado en código (archivo:línea).
- **PARCIAL** — Mecanismo presente pero incompleto o no invocado en todas las rutas.
- **FALTA** — No implementado.
- **DOC** — Regla superada/reinterpretada por el diseño actual; requiere reconciliar el texto.

## Observación clave

El mecanismo de desactivación con cascada (`Member#deactivate!`) y la invalidación de
certificados (`holder_deactivated?`/`downloadable?`) **ya existen y funcionan**. La mayoría
de los gaps de identidad (BR-029/034/057/059/069/095/096/097/099) se cierran con un único
cambio: **invocar `deactivate!` sobre el `Member` anterior al detectar un RUN duplicado**,
en las dos rutas de aprobación. Ver ADR-006 (servicio compartido de transferencia de
identidad) y TASK-004 / TASK-018.
